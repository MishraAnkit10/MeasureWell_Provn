Deliberate decisions in this sketch

The partner sees the same network number as the CEO. If the two views could ever disagree, we would be back where we started on Monday.

The view says what it does not have. Riverbend asked the Field Coach about its cohort. This table holds one row per organization, so the honest answer is "not here yet".

The lock is in the warehouse, by a rule that returns only the partner's own row, not by a filter in the dashboard tool that someone can remove.

(b) Corrected metric: models/metric_partner_on_track.sql

-- "On Track rate" = partners On Track / all real, consenting partner organizations.
-- This is the only place the metric is computed. Dashboards and the Field Coach read the result.
with cleaned as (
    select
        partner_id,
        consent_to_share,
        -- DECISION: fix spelling here, not in each report. Trim, lowercase, and treat "_" as a space,
        -- so 'on_track', 'ON TRACK' and 'on track' all become 'On Track'.
        -- Anything unrecognised becomes 'Unmapped'. It stays in the total, because it is still a partner,
        -- and the test on this model stops the run while any exist.
        case lower(replace(trim(assessment_stage), '_', ' '))
            when 'on track'      then 'On Track'
            when 'needs support' then 'Needs Support'
            when 'not started'   then 'Not Started'
            else 'Unmapped'
        end as assessment_stage
    from fct_partner_assessment            -- in dbt: {{ source('warehouse', 'fct_partner_assessment') }}
    -- DECISION: remove test records by ID from a reviewed list (a dbt seed in production), not by
    -- guessing from the name. The ticket asks the loader owner for a proper is_test flag.
    where partner_id not in ('P-010')
),
shareable as (
    -- DECISION: the CEO quotes this number to funders, so it is an external number.
    -- Consent is required. Mesa Futures (consent = false) is left out. Needs CAIDO approval.
    select * from cleaned where consent_to_share = true
)
select
    count(*)                                                             as partners_in_scope,       -- 10
    sum(case when assessment_stage = 'On Track'      then 1 else 0 end)  as partners_on_track,       -- 5
    sum(case when assessment_stage = 'Needs Support' then 1 else 0 end)  as partners_needs_support,  -- 4
    sum(case when assessment_stage = 'Not Started'   then 1 else 0 end)  as partners_not_started,    -- 1
    sum(case when assessment_stage = 'Unmapped'      then 1 else 0 end)  as partners_unmapped,       -- 0, must stay 0
    -- DECISION: Not Started stays in the denominator. Dropping it (as the old dashboard did)
    -- makes the network look better simply because a partner has not been assessed.
    round(1.0 * sum(case when assessment_stage = 'On Track' then 1 else 0 end)
              / nullif(count(*), 0), 4)                                  as on_track_rate            -- 0.50
from shareable

(c) The test that would have caught the 33%: models/schema.yml

# The 64% was a different problem: the dashboard did its own maths. The model above, which it now reads, fixes that.
sources:
  - name: warehouse
    tables:
      - name: fct_partner_assessment
        columns:
          - name: assessment_stage
            tests:
              - not_null
              # DECISION: test the RAW column, before cleaning. On Monday's data this fails on 3 rows:
              # P-002 'on_track', P-004 'ON TRACK', P-009 'on track': the rows the 33% pull missed.
              # Severity is "warn" because we do not own the loader and must not block the nightly
              # run. The test that blocks is on the model, below.
              - accepted_values:
                  values: ['On Track', 'Needs Support', 'Not Started']
                  config:
                    severity: warn

models:
  - name: metric_partner_on_track
    columns:
      - name: partners_unmapped
        tests:
          # DECISION: severity "error" (the default). If any stage spelling is not recognised,
          # the run fails before the dashboard updates, so a wrong number is never published.
          - accepted_values:
              values: [0]
              quote: false

How this was checked. Run on the 12 rows in SQLite: the old dashboard logic gives 7 of 11, the exact text pull 4 of 12. With one stage misspelled on purpose, partners_unmapped becomes 1 and the model test fails.
